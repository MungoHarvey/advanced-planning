## Problem Statement

The pipeline can *check* (gate review) and *build* (loops), but a gate failure dead-ends
at a human: `/next-phase`'s gate-fail path creates a versioned retry file with injected
failure context and then STOPs. Even under `--auto` the stop table says *"Gate FAIL →
create versioned retry, STOP (manual review required)."* We want the pipeline to be
self-correcting: on gate fail, automatically remediate the specific findings, then re-gate
with fresh, independent agents, bounded so it cannot spin forever. The hard constraint,
surfaced by review: this must be **self-correction, not automated negotiation with the
gate** — remediation must not be able to weaken the target to force a pass.

## What This Tunes (not net-new)

Reuses `create_retry_version` + `inject_failure_context` (`versioning.py`), the verdict
schema's `findings` / `loops_to_revert` / `failure_notes`, fresh-agent gate spawns, the
escalation STOP, and the `gate_failure_context` schema. The change is turning one STOP
into a bounded, guard-railed `continue`.

## Decisions (brainstorming + eng-review + codex, all folded in)

1. **Granularity = hybrid triage, two independent inputs.** `triage_findings(verdict)`
   routes from fields that actually exist:
   - `loops_to_revert` → **structural** → re-run those loops (ralph-loop-worker)
   - `findings` with `severity == "critical"` AND an actionable file/line in `location` →
     **localized** → focused-fix agent edits them
   - critical finding with no actionable location and not covered by a reverted loop →
     **unfixable** → escalate early (don't burn a cycle)
   No finding→loop inference (findings carry a freeform `location` string, not a loop id;
   there is no per-finding confidence — confidence is verdict-level, so triage keys on
   `severity`). Overlap (a re-run loop also fixing a localized finding) is harmless.
2. **Blindness = defense in depth, but blind to FAILURE CONTEXT not to the CONTRACT.**
   Worker-facing failure context moves to a worker-only sidecar
   (`.advanced-plans/phases/phase-N/retry-context.json`), out of `loops.md` frontmatter;
   re-run worker and focused-fix agent read it directly. Gate agents get an isolation rule
   (in `core/agents/gate-reviewer.md`, inherited by the CC gate agents): never read
   `retry-context.*`, `gate-verdicts/`, or prior verdicts. BUT re-gate agents must still
   evaluate the **original frozen criteria** and emit `criteria_outcomes` for **every**
   criterion (see Remediation Safety) — blind to what failed, not to what's required.
3. **Autonomy = on by default within `--auto`, bounded 2 cycles.** `--auto` is the consent
   boundary. Cycle count = number of `gate_fail` events for this phase in `history.jsonl`
   (NOT the `attempt = verdict_count / agent_count` division, which Phase 12's degradable
   Codex already breaks). At 2 cycles still failing → fall back to today's versioned-retry +
   STOP. Without `--auto`, gate-fail is byte-for-byte today's behavior.

## Remediation Safety (the spine — without this it is gate-gaming)

1. **Diff allowlist.** A remediation cycle may only modify source files. It must NEVER
   touch: `.advanced-plans/phases/**/plan.md`, `loops.md` (success criteria / todos),
   `core/schemas/**`, `core/state/**`, `platforms/python/tests/**` asserting the failed
   criteria, the gate-agent / reviewer docs, or `gate-verdict*` files. The controller
   validates the remediation `git diff --name-only` against the allowlist BEFORE commit;
   any out-of-bounds path → abort the fix, escalate (do not re-gate).
2. **Frozen criteria.** Before the first cycle, snapshot the phase plan's success-criteria
   block (hash + copy) to `phase-N/criteria-frozen.md`. Re-gate agents evaluate the frozen
   contract; the controller asserts the live criteria hash still matches before each
   re-gate. Criteria changed → abort + escalate.
3. **Full criteria_outcomes on re-gate.** Every re-gate verdict MUST emit a
   `criteria_outcomes` entry for ALL frozen criteria (not just the failed ones). The
   controller rejects a re-gate verdict missing any criterion → escalate. Stops a blind
   fresh agent from rubber-stamping by spot-checking.

## Git-State Policy

- **Staged allowlist, never `git add -A`.** The remediation commit stages only the
  allowlisted source paths the fix touched. Transient state (`gate-verdicts/`,
  `history.jsonl`, `retry-context.json`, `loop-ready.json`, `loop-complete.json`,
  `gate-review-mode`) is committed by its own existing steps, not bundled into the fix.
- **Pre-remediation snapshot.** Before cycle 1, record the pre-remediation commit SHA. On
  escalation after failed fixes, the versioned-retry is built from a defined baseline
  (default: pre-remediation snapshot, so bad fixes are not silently baked in; the bad-fix
  tree is preserved on a `phase-N-remediation-attempts` ref for inspection).
- **No-change detection excludes transient files.** "Fix produced no change → escalate"
  compares the diff of allowlisted source paths only, ignoring retry-context / history /
  verdicts (which always change).
- **Dirty-tree preflight.** Unrelated dirty changes when remediation starts → escalate
  rather than commit them into a fix.

## Composition Rules (interaction with existing /next-phase --auto)

- **`--force` / `--skip-gate`:** unchanged precedence — `--force` short-circuits gate-fail
  handling (advance anyway) and therefore skips remediation; `--skip-gate` = no gate, no
  remediation. `--auto --force` = advance on fail, no remediation.
- **Loop-fail during structural remediation:** if a re-run loop itself fails (worker
  `status: failed`), that is NOT a remediation cycle — it hits the existing loop-fail STOP
  (next-phase.md:252) and escalates immediately. Cycles count gate re-evaluations only.
- **Contradictory findings:** unioned critical findings prescribing incompatible edits to
  the same location → the controller does not guess; escalate with a `remediation_conflict` note.
- **Post-repair advance guard:** a phase passing only after remediation (cycles ≥ 1) records
  a `passed_after_remediation` flag in the `gate_pass` event. Under `--auto`, advancing is
  allowed but the flag is carried so a later audit / policy can require human sign-off before
  building further on a repaired foundation. (v1: flag + advance; gating on it is a follow-on.)

## Control Flow

Replaces the gate-fail branch of `/next-phase` Step 7, active only under `--auto`:

```
gate fail at attempt k   (sentinel was UP for the gate; controller removes it now)
  cycles = count(history gate_fail events, phase=N)
  ├─ cycles >= 2  → ESCALATE: versioned retry (from pre-remediation snapshot) + STOP
  └─ else → REMEDIATE:
        first cycle: record pre-remediation SHA; freeze criteria -> criteria-frozen.md
        triage = triage_findings(verdict)              # structural / localized / unfixable
        if unfixable non-empty OR contradictory         → ESCALATE
        ASSERT gate-review-mode sentinel ABSENT          # else hook blocks every edit (exit 2)
        write failure context -> phase-N/retry-context.json   (worker-only; NOT loops.md)
        structural: re-run each loops_to_revert loop (worker reads retry-context.json)
                    a loop fails -> loop-fail STOP (escalate)
        localized:  focused-fix agent (analysis-worker) edits ONLY allowlisted source
        VALIDATE git diff --name-only ⊆ allowlist        → else ESCALATE
        if no change to allowlisted source               → ESCALATE
        git add <allowlisted paths only> && commit "remediate: phase-N cycle"
        append gate_remediation event (structural/localized counts)
     → RE-GATE attempt k+1: sentinel UP; FRESH agents (blind to failure context,
        evaluating frozen criteria, emit criteria_outcomes for ALL); sentinel DOWN
     → loop
```

```
ASCII: loop, two exits, guard rails

   ┌──────────────────────────────────────────────┐
   │ gate (attempt k) [sentinel UP -> DOWN]         │
   └───────────────┬──────────────────────┬─────────┘
              pass │                  fail │  cycles>=2 ? ── yes ─► versioned retry
                   ▼                       ▼                        (from pre-rem snapshot)
            advance (+passed_after_         no                       + STOP
             remediation if k>1)            │
                                            ▼ triage
                             unfixable / conflict ── yes ─► ESCALATE
                                            │ no
                                            ▼ assert sentinel DOWN
                                  structural: re-run loops (loop-fail -> STOP)
                                  localized:  fix ALLOWLISTED source only
                                            ▼ diff ⊆ allowlist? changed?
                                      check fail ── ─► ESCALATE
                                            │ ok
                                      commit (staged allowlist)
                                            ▼
                                  re-gate (k+1, frozen criteria) ─┐
                                            ▲                      │
                                            └──────────────────────┘
```

- ✓ `remediate.py`; `triage_findings` returns `{structural, localized, unfixable}`, keys on

- ✓ `core/agents/gate-reviewer.md` states the isolation rule; CC agents inherit (no duplication).
- ✓ Diff allowlist enforced: a cycle touching a forbidden path aborts + escalates (tested).
- ✓ Frozen criteria written before cycle 1; re-gate evaluates it; hash mismatch → escalate;
  re-gate verdict missing any criterion → escalate.
- ✓ Git-state: commit stages only allowlisted source (no `git add -A`); no-change excludes
  transient files; pre-remediation SHA recorded; dirty-tree preflight escalates.
- ✓ Cycle count from `history.jsonl` gate_fail events; bound 2 → versioned-retry+STOP from
  the pre-remediation snapshot.
- ✓ Composition: `--force`/`--skip-gate` skip remediation; failing re-run loop → loop-fail
  STOP; contradictory findings escalate; `passed_after_remediation` recorded on a repaired pass.

## NOT in scope

- New top-level command (reuses `/next-phase --auto`).
- Auto-fixing warnings/info findings (gate fails only on critical).
- Gating `--auto` advance on `passed_after_remediation` (v1 records; enforcement is follow-on).
- Structured `findings[].location` (file/line/loop) or per-finding confidence in the verdict
  schema — triage works on the freeform string + severity for v1; structured locations would
  improve precision; deferred.
- Cross-phase remediation.
- Codex as the re-gate reviewer here (Phase 12 codex path composes unchanged — a codex
  verdict is just another failing verdict feeding triage).
