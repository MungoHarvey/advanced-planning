# Design: Self-Correcting Gate (Gate-Remediation Loop)

Generated by /brainstorming on 2026-06-08
Branch: main
Repo: advanced-planning
Status: DRAFT
Type: Tuning (extends existing gate / next-phase machinery)

## Problem Statement

The pipeline can *check* (gate review) and *build* (loops), but a gate failure
dead-ends at a human: `/next-phase`'s gate-fail path creates a versioned retry file with
injected failure context and then STOPs ("Run /next-loop to begin retry"). Even under
`--auto`, the stop table is explicit: *"Gate FAIL → create versioned retry, STOP (manual
review required)."* We want the pipeline to be self-correcting: on gate fail, automatically
remediate the specific findings, then re-gate with fresh, independent agents, bounded so it
cannot spin forever. This closes the loop so the pipeline can check-and-build.

## What This Tunes (not net-new)

Almost all the machinery exists. The change is turning one `STOP` into a bounded
`continue`. We reuse: `create_retry_version` + `inject_failure_context` (`versioning.py`),
the verdict schema's `findings` / `loops_to_revert` / `failure_notes`, the existing gate
`attempt` counter, fresh-agent gate spawns, and the escalation STOP as the fallback.

## Decisions (from brainstorming)

1. **Granularity = hybrid triage.** Each critical finding (confidence ≥80) is routed by
   type, using signals already in the verdict:
   - finding's loop ∈ `loops_to_revert` → **structural** → re-run that loop (ralph-loop-worker)
   - finding has a file/line `location`, not loop-scoped → **localized** → focused-fix agent edits it
2. **Blindness = defense in depth.** Worker-facing failure context moves to a worker-only
   sidecar (`.advanced-plans/phases/phase-N/retry-context.json`), out of `loops.md`
   frontmatter. PLUS an explicit isolation rule on the gate-reviewer contract: gate agents
   never read `retry-context.*`, `gate-verdicts/`, or prior verdicts — they evaluate
   criteria against artifacts only. Physical boundary + instruction.
3. **Autonomy = on by default within `--auto`, bounded 2 cycles.** `--auto` is the consent
   boundary; no separate flag. Bounded at 2 remediation cycles (3 total gate attempts);
   if still failing, fall back to today's versioned-retry + STOP (escalate to human).
   Without `--auto`, gate-fail behaves exactly as today.

## Control Flow

Replaces the gate-fail branch of `/next-phase` Step 7, active only under `--auto`:

```
gate fail at attempt k
  ├─ k >= 3  (2 remediation cycles already used)
  │     → ESCALATE: versioned retry + STOP  (today's behavior, unchanged)
  └─ else → REMEDIATE (cycle k):
        read failing verdict(s): findings, loops_to_revert, failure_notes
        triage = triage_findings(verdict)
          structural (loops_to_revert)  → re-run each loop via ralph-loop-worker
                                           (failure context delivered via sidecar -> loop-ready.json)
          localized  (file/line finding) → focused-fix agent edits the named file/line
        write failure context to .advanced-plans/phases/phase-N/retry-context.json  (NOT loops.md)
        git commit "remediate: phase-N cycle-k"
     → RE-GATE at attempt k+1: spawn FRESH gate agents (blind — isolation rule)
     → append history event; loop
```

The cycle counter is the existing gate `attempt` number — no new state. Attempt 1 fail →
remediate → attempt 2 → fail → remediate → attempt 3 → fail → escalate.

```
ASCII: the loop and its two exits

   ┌───────────────────────────────────────────────┐
   │  gate review (attempt k)                        │
   └───────────────┬─────────────────────┬───────────┘
                   │ pass                 │ fail
                   ▼                      ▼
              advance phase        k >= 3 ?
                                 ┌────┴─────┐
                            yes  │          │ no
                                 ▼          ▼
                       versioned retry   triage findings
                       + STOP (human)    ┌──────┴───────┐
                                    structural      localized
                                    re-run loop     focused fix
                                         └─────┬────────┘
                                          commit remediation
                                               │
                                               ▼
                                       re-gate (attempt k+1)  ──┐
                                               ▲                │
                                               └────────────────┘
```

## Data Flow — the two context channels

```
                        ┌─ retry-context.json (sidecar) ─┐
failing verdict ──────► │  findings, do_not_repeat,       │ ──► focused-fix agent (reads directly)
(gate-verdicts/)        │  loops_reverted                 │ ──► orchestrator ──► loop-ready.json ──► ralph-loop-worker
                        └─────────────────────────────────┘
                                                              (loops.md stays CLEAN of failure context)

re-gate agents ──► phase plan (criteria) + produced artifacts + loops.md handoffs ONLY
                   (isolation rule: must NOT read retry-context.* or gate-verdicts/)
```

## Error Handling / Edge Cases

- **Bound exhausted (k≥3):** fall back to existing versioned-retry + STOP. Human review,
  no behavior change from today.
- **No `loops_to_revert` but critical findings exist:** all findings treated as localized
  → focused fix. If a localized fix is ambiguous (no actionable file/line), that finding
  cannot be auto-fixed → escalate early (don't burn cycles on an unfixable finding).
- **Remediation makes no change** (fix agent edits nothing): treat as a failed cycle; do
  not re-gate on an unchanged tree — escalate.
- **A fix introduces a regression** caught by the re-gate: that's the loop working; it
  counts as a cycle and either fixes next cycle or escalates at the bound.
- **`--force` / `--skip-gate`:** unchanged; remediation only engages on a real gate fail
  under `--auto`.
- **Conflicting findings across agents:** union the critical findings from all failing
  verdicts before triage.

## Testing

- `test_remediate.py` (unit, zero-dep): triage routes loops_to_revert→structural;
  file/line finding→localized; finding with no actionable location→flagged unfixable;
  multi-agent finding union; empty findings→empty triage.
- Bound test: a stub sequence of 3 failing verdicts results in escalation at attempt 3
  (assert the controller stops, not loops). (Unit-level on the controller's bound predicate;
  the markdown control flow is traced + documented like the codex wiring.)
- Isolation: assert gate-reviewer.md + the two CC agent docs contain the isolation rule;
  grep that the re-gate prompt does not reference retry-context / prior verdicts.
- Channel: `inject_failure_context` writes `retry-context.json` and does NOT write
  `gate_failure_context` into loops.md frontmatter; orchestrator surfaces it in loop-ready.json.
- Regression: existing `versioning.py` tests updated for the retarget; all current tests pass; AST NONE.

## Success Criteria

- ✓ `remediate.py` exists with `triage_findings`; zero-dep (AST NONE); tests cover all routing cases.
- ✓ `inject_failure_context` writes `.advanced-plans/phases/phase-N/retry-context.json`;
  `loops.md` frontmatter no longer receives `gate_failure_context`; orchestrator folds the
  sidecar into `loop-ready.json`; tests updated and passing.
- ✓ `core/agents/gate-reviewer.md` (+ both CC gate agents) state the isolation rule; re-gate
  prompts never reference prior verdicts or retry-context.
- ✓ `/next-phase` under `--auto`: on gate fail with k<3, runs triage→fix→re-gate and appends
  a `gate_remediation` event per cycle; at k≥3 falls back to versioned-retry + STOP.
- ✓ Without `--auto`, gate-fail behavior is byte-for-byte today's behavior (no regression).
- ✓ Full test suite passes; AST NONE; LOCKED files byte-unchanged.

## Distribution

No new artifact or command. Ships in the framework via the existing install copy of
`core/` + `platforms/`. New python module covered by existing pytest/AST CI.

## NOT in scope

- New top-level command (reuses `/next-phase --auto`).
- Auto-fixing warnings/info findings — the gate only fails on critical ≥80, so remediation
  targets exactly those; non-blocking findings stay advisory.
- Cross-phase remediation (a fail in phase N never reaches back into phase N-1).
- Codex as the re-gate reviewer here — orthogonal; the Phase 12 codex path composes with
  this unchanged (a codex verdict is just another failing verdict feeding triage).
- Tuning the triage heuristic with ML/heuristics beyond the loops_to_revert vs file/line split.

## Open Questions

- **retry-context.json schema:** does it warrant a formal `core/state/` schema, or is it an
